# 문서·백업·복원과 삭제

2026-11-16. Docker 없이 프로젝트의 Python/Node 및 Windows 네이티브 실행 파일을 사용한다.

## 원본과 소견

**문서 · OCR** 메뉴에서 PDF/PNG/JPEG를 선택한다. 원본 바이너리/SHA-256·페이지 이미지·추출 방법과 텍스트를 구별해 보존한다. PDF 최대 50쪽/32 MiB, 이미지/렌더링 페이지 최대 2천만 픽셀이다. 추출 실패도 원본은 남는다. 직접 입력과 문서 전사는 다른 출처다. 원본/선택 검사와 전사 텍스트를 확인하고 수정한 후 저장한다. 이 확인은 병원 문서 진위나 의학적 정답 인증이 아니다.

OCR 언어 파일과 WASM은 로컬에서 읽는다. 설치: `npm ci`, `setup-ocr.ps1`. `ocr-runtime-lock.json`의 공식 저장소 고정 커밋·SHA로 재현한다. Windows 소유 작업 객체로 OCR/문장 모델 자식 프로세스를 묶어 앱 종료 시 남지 않게 한다. 중단된 문서 추출은 재시작 후 실패로 표시하며 원본을 다시 선택해 등록할 수 있다.

## 백업

**백업 · 데이터 관리 → 현재 작업 공간 백업**. 진행 중인 등록·분석·문서 작업이 없어야 한다. SQLite의 일관된 복사본, 앱 원본 DICOM 복사본·분석 산출물·문서 원본/페이지·소견/검토/정리본을 포함한다. 고정 모델 런타임, 재생성 가능한 영상 캐시, 기존 백업·복구/삭제 대기는 제외한다. ZIP 내 파일 목록·크기·SHA를 검사한 뒤 완성본만 표시한다. 다운로드하고 **검증·복원 안내**로 확인한다. 백업에도 의료정보가 포함되므로 본인이 관리하는 저장 위치에 보관한다.

## 오프라인 복원

1. 해당 ZIP을 프로젝트의 `data/backups/{백업ID}.zip`에 둔다. 파일명을 임의 실행 경로나 명령으로 사용하지 않는다.
2. 앱과 네이티브 영상 서비스를 종료한다. 8000/8042 포트가 실행 중이면 복원을 거부한다.
3. 프로젝트 PowerShell에서 `./restore-backup.ps1 -BackupId {백업ID}` 실행 후 안내된 **RESTORE {백업ID}**를 입력한다.
4. 구조·경로·중복·해시·DB 무결성/FK 검사 후 관리 데이터만 교체한다. 교체 전 DB/원본·영상 캐시/삭제 대기는 `data/recovery/{복구ID}`로 보존한다. 오류 시 이동을 되돌린다.
5. `start.cmd`로 실행한다. Orthanc 캐시는 원본에서 다시 구성한다. 외부의 원래 CT 폴더, 모델 파일, 기존 백업은 교체하지 않는다.

실제 운영 데이터에 자동 복원/삭제 시험을 하지 않았다. 복원 인수는 격리된 자료에서 검증했다. 완전한 새 PC의 AI/영상 런타임 재설치는 아직 별도 인수 항목이다.

## 검사 삭제

선택 검사의 **삭제 범위 확인**을 먼저 읽고 **DELETE {검사ID}**를 입력해야 실행된다. 앱 원본 복사본·해당 분석/문서/소견/검토와 영상 미러만 제거한다. 선택했던 외부 CT 폴더, 백업·복구 보관본은 유지한다. 저장장치의 보안 소거 기능이 아니다.

파일이 잠기면 DB 확정 전에는 이동을 되돌린다. 프로세스 중단 전 파일 이동도 다음 시작에 복구한다. DB 삭제 확정 뒤 남은 잠긴 파일은 메뉴에 정리 대기로 표시하고 **정리 재시도**로 제거한다. 현재 앱이 관리하지 않는 경로를 넘겨 재귀 삭제할 수 없다.
